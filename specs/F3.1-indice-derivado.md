# Encargo F3.1 — índice derivado

## Contexto en cinco líneas

La bóveda markdown queda como fuente de verdad y se sigue revisando en PR. Lo que
se agrega es un **índice compilado desde ella** a SQLite: consultable, validable y
desechable. No se migra nada, no se toca ninguna nota. Si el índice se corrompe se
borra y se regenera. Nunca entra a git.

Diseño completo y diagramas: preguntale a Fernando por el artefacto *"Bóveda compilada"*.

## Entregables

### 1. `contexto/.control/esquema.sql`

Seis tablas. `nota` como eje; `scope`, `simbolo`, `enlace` y `deuda` referencian
`nota(ruta)` con `ON DELETE CASCADE`; más `nota_fts` virtual.

Restricciones que **no son opcionales** — son el punto entero del cambio:

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- en nota
CHECK (tipo   IN ('adr','patron','referencia','deuda','sesion','modulo',
                  'caso','qa','plan','indice','protocolo','moc'))
CHECK (estado IN ('vigente','borrador','archivado','obsoleto'))
CHECK (fecha GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]')
CHECK (actualizado >= fecha)

-- en scope: una ruta lleva barra; Result<T> no es una carpeta
CHECK (instr(ruta_codigo, '/') > 0)
CHECK (ruta_codigo NOT GLOB '*[<>()]*')

-- en deuda: el emoji del titulo manda sobre donde vive el item
CHECK (id GLOB 'P-[0-9][0-9][0-9]')
CHECK (severidad IN ('critico','importante','menor'))
CHECK (estado IN ('abierto','resuelto'))
CHECK (severidad = seccion)

-- fts5: espanol con tildes
CREATE VIRTUAL TABLE nota_fts USING fts5(
  ruta UNINDEXED, titulo, resumen, cuerpo,
  tokenize = "unicode61 remove_diacritics 2");
```

Columnas: `nota(ruta PK, titulo, tipo, estado, carpeta, fecha, actualizado, resumen,
resumen_fijo, bytes, hash)`; `scope(nota FK, ruta_codigo, existe, PK(nota,ruta_codigo))`;
`simbolo(nota FK, nombre, PK(nota,nombre))`; `enlace(origen FK, destino, resuelto,
PK(origen,destino))`; `deuda(id PK, severidad, seccion, estado, titulo, nota FK, detectado_en)`.

Índices en `scope(ruta_codigo)`, `simbolo(nombre)`, `enlace(destino)`, `nota(tipo,estado)`.

### 2. `build-index.js` emite además `contexto/.control/indice.db`

- Usá `node:sqlite` (viene con Node 24, **no instales nada**).
- Borrá y recreá el archivo en cada corrida. Es derivado: no hay migraciones.
- `scope.existe` = 1 si la ruta existe en el repo (`fs.existsSync` desde la raíz), si no 0.
- `enlace.resuelto` = 1 si el destino resuelve a una nota existente. Reusá la lógica
  de `resolverEnlace()` de `verificar-boveda.js` — maneja pipes escapados y el caso
  de `#` dentro del nombre (`[[Convenciones C#]]`).
- `deuda`: parseá `40 - Proyecto Bimbo/Deuda Técnica - Pendientes.md` y `- Resueltas 2026.md`.
  `severidad` sale del emoji en el título del ítem (🔴 crítico, 🟡 importante, 🟢 menor);
  `seccion` sale del `##` bajo el que vive físicamente.
- **Los CHECK van a fallar en la primera corrida.** Es lo esperado y es el valor:
  hay 62 `scope` inválidos y 3 ítems de deuda mal ubicados. Emití el `.db` en modo
  tolerante (`--laxo`) que salta e informa las filas rechazadas, en vez de abortar.
  Arreglar los datos es F3.2, no esta fase.

### 3. `scripts/consultar.js`

```
codigo <ruta>     notas cuyo scope es prefijo de esa ruta, ordenadas por 'actualizado' asc
simbolo <nombre>  notas donde aparece ese simbolo
buscar "texto"    FTS5 sobre titulo+resumen+cuerpo
deuda [--abierta] [--severidad critico|importante|menor]
sesiones [--desde YYYY-MM] [--limite N]
salud             scopes muertos, enlaces rotos, notas huerfanas, filas rechazadas
```

Salida legible para humanos y agentes: título, resumen y ruta. **Objetivo duro:
menos de 300 tokens por consulta.** Si una consulta devuelve más de 15 filas, cortá
y decí cuántas quedaron.

Agregá `contexto/.control/indice.db*` (el `*` cubre `-wal` y `-shm`).


La prueba de las tildes (`buscar "paginacion"` encontrando «paginación») es la que
confirma que el tokenizador quedó bien configurado. Si falla, revisá `remove_diacritics 2`.
